==================================================
AUG 11–23 — FIRST-PASS THEORY
==================================================

AUG 11 — IAM FOUNDATIONS
Authentication vs authorization; users; groups; roles; human vs workload
identities; long-term vs temporary credentials; least privilege.
System design: trust boundaries and credential exposure.
Practice: 5–10 IAM scenarios.

AUG 12 — IAM DEEP DIVE + STS
Policies; identity/resource policies; policy evaluation; explicit deny; STS;
AssumeRole; temporary credentials; federation; programmatic access;
cross-account access.
System design: authorization boundaries and workload identity.
Practice: 10–15 IAM questions.

AUG 13 — KMS + SECRETS + COGNITO
KMS; encryption; key rotation; cross-account encryption; Secrets Manager;
Parameter Store; Cognito; bearer tokens; application authorization.
System design: security boundaries, secret distribution, tenant isolation.
Practice: security scenarios and comparisons.

AUG 14 — LAMBDA CORE
Execution/invocation models; sync vs async; event sources; runtime; handler;
memory; timeout; environment variables; layers; versions; aliases.
System design: statelessness and horizontal scaling.
Practice: Lambda scenarios.

AUG 15 — LAMBDA ADVANCED
Concurrency; reserved/provisioned concurrency; retries; destinations; DLQs;
permissions; VPC access; testing; performance; idempotency; real-time
processing.
System design: downstream protection, retry storms, failure isolation.
Practice: 10–15 Lambda questions.

AUG 16 — API GATEWAY + SDK/API BEHAVIOR
Integrations; transformations; validation; auth; throttling; caching; stages;
custom domains; errors; SDK calls; retries; backoff; timeouts; idempotency.
System design: API boundaries, rate limiting, dependency failures.
Practice: API/SDK scenarios.

AUG 17 — DYNAMODB CORE
Tables; partition/sort keys; access patterns; high-cardinality keys; Query vs
Scan; GSI/LSI; strong vs eventual consistency.
System design: access-pattern modeling, partitioning, consistency.
Practice: DynamoDB scenarios.

AUG 18 — DYNAMODB ADVANCED + S3
DynamoDB capacity; conditional writes; transactions; TTL; Streams; DAX; hot
partitions; throttling; caching; lifecycle. S3 buckets/objects/versioning/
lifecycle/storage classes/encryption/policies/presigned URLs/events/replication.
System design: caching, event processing, object storage.
Practice: DynamoDB + S3 questions.

AUG 19 — SQS + SNS
Standard/FIFO; visibility timeout; long polling; DLQ; retries; ordering;
at-least-once delivery; Lambda integration; SNS topics/subscribers/fanout/
filtering.
System design: queues vs pub/sub, loose coupling, backpressure.
Practice: 10–15 messaging questions.

AUG 20 — EVENTBRIDGE + STEP FUNCTIONS
Event buses/rules/patterns/targets/scheduling; state machines; Task/Choice/
Parallel/Retry/Catch; orchestration; choreography; fanout.
System design: event-driven architecture and choreography vs orchestration.
Practice: EventBridge vs SNS vs SQS and Step Functions scenarios.

AUG 21 — OBSERVABILITY + TROUBLESHOOTING
CloudWatch logs/metrics/alarms/dashboards/Insights/structured logging/custom
metrics/EMF; X-Ray traces/service maps/annotations; CloudTrail; health checks;
readiness; debugging.
System design: observability and distributed-system debugging.
Practice: troubleshooting scenarios.

AUG 22 — DEPLOYMENT / CI-CD
CloudFormation; SAM; CDK; CodeBuild; CodeDeploy; CodePipeline; AppConfig;
CodeArtifact; artifacts; environments; aliases; rollbacks; blue/green;
canary; rolling; integration testing; mocking; event-driven testing.
System design: deployment safety, blast radius, progressive delivery.
Practice: deployment scenarios.

AUG 23 — SUPPORTING SERVICES + FULL COVERAGE CHECK
EC2; EBS; EFS; ECS; Fargate; ECR; EKS awareness; Elastic Beanstalk; VPC
developer concepts; Route 53; ELB; CloudFront; WAF; AppSync; Kinesis; Athena;
OpenSearch; Systems Manager; Amplify; CloudShell; Amazon Q Developer.

Do not deep-dive every supporting service. Learn the problem, use case, and
exam-relevant behavior.

SEP 3 — EXAM DAY
==================================================

Light review only.

During the exam:
- Read the requirement carefully.
- Identify what is actually being asked.
- Watch for clues such as MOST appropriate, LEAST operational overhead,
  MOST secure, cost-effective, high availability, minimal changes,
  asynchronous, ordered, durable, least privilege.
- Eliminate distractors.
- Do not get stuck on one question.
- Flag and return to uncertain questions.
